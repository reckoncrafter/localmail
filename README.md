# localmail

Localmail is a docker container that provides a simple means of collecting arbitrary data from a web server and
making it available as if it were email.

It accepts data at an HTTP API endpoint: `/send`, in the form of a JSON document, e.g.:

```json
{
 "subject": "Form Submission Notification",
 "from": "user@mail.com",
 "body": "content..."
}
```

> This project currently uses the Flask development server, and the API is fixed on port 8080.

The endpoint can be tested with cURL:
```bash
$ curl --location 'http://localhost:8080/send' \
--header 'Content-Type: application/json' \
--data-raw '{
 "subject": "Form Submission Notification",
 "from": "user@mail.com",
 "body": "content..."
}'
```

These documents are converted into email format and submitted to Mailcot via an LMTP request, which Dovecot
delivers to a Maildir at `/var/mail/$MAIL_USER/Maildir`

Dovecot then makes these emails available over IMAP.

Dovecot is also set up to provide a submission (SMTP) service.
Because nearly all email clients won't allow a mailbox to be configured
with only IMAP or POP3, which would be receive-only, the container also exposes this SMTP service.

The submission service relays to a simple postfix relay, which relays back to dovecot's LMTP service. This allows
mail clients to send messages to it's own mailbox (some clients do this as part of set up to check that the server is working),
but will always bounce emails sent to other users or domains.

> This project is currently hardcoded to create just one user and one mailbox.
> In the future, I plan to add support for multiple mailboxes, in which case those mailboxes could also send mail between each other.

Here's an example docker-compose.yml to build the container:
```yml
services:
  mail:
    container_name: localmail
    build: ./localmail
    ports:
      - "127.0.0.1:8080:8080" # HTTP API
      - "993:993" # IMAPS
      - "143:143" # IMAP
      - "587:587" # SMTP
    volumes:
      - mail_data:/var/mail
    restart: none
    configs:
      - mail_env
    secrets:
      - certificate.pem
      - privatekey.pem

volumes:
  mail_data:
    # External volume for persistent storage of mailbox content

configs:
  mail_env:
    file: # Points to a .env file containing definitions for:
      # MAIL_USER (mailbox username)
      # MAIL_DOMAIN (mailbox domain. This can really be anything you want.)
      # MAIL_PASSWD (password to authenticate over SMTP and IMAP)

secrets:
  certificate.pem:
    # Points to the SSL certificate used to encrypt IMAP and SMTP
  privatekey.pem:
    # Points to the SSL private key used to sign the certificate.
```

# Installation

This project requires `docker` and `docker-compose`. To install Docker, follow the instructions in [Install Docker Engine](https://docs.docker.com/engine/install) and
[Overview of installing Docker Compose](https://docs.docker.com/compose/install)

You'll need to write your own `docker-compose.yml` using the template provided above. In general, leave alone lines that aren't commented out.

## Volume: Mail Data

The `mail_data` volume is where the mailbox will live. Leaving this line as is will create a volume in Docker's default volume directory, but if you want the `Maildir` to be in a convenient location,
you can rewrite this line with the path you want the volume stored at
```yml
volumes:
  mail_data:/home/user/mail
```

## Config: Mail Env

The `mail_env` config is another file that you need to create in this directory, containing environment variable definitions that the container will use to configure its mailbox.
```sh
#!/bin/sh
# mail.env
MAIL_USER="user"
MAIL_DOMAIN="example.local"
MAIL_PASSWD="strong_password"
```

## Secrets: SSL Certificates
To encrypt your IMAP and SMTP connections, you'll need to add an SSL certificate and private key. If you're hosting this on a web server that already has a key and certificate to serve HTTPS, 
you can point this at those same keys. If you're using Certbot, that may look like this:
```yml
secrets:
  certificate.pem:
    /etc/letsencrypt/live/<domain>/fullchain.pem
  privatekey.pem:
    /etc/letsencrypt/live/<domain>/privkey.pem
```

If you're hosting this on its own, it may not be necessary to provision encryption keys from a Certificate Authority, as most email clients will let you use a self-signed certificate.

On Linux, you need `openssl` to generate a signed certificate. For full instructions, you can follow [this tutorial on Linuxize](https://linuxize.com/post/creating-a-self-signed-ssl-certificate/)

On Windows, you'll still need `openssl` to convert the `PFX` generated by `New-SelfSignedCertificate` to the `PEM` format. The easiest way to get OpenSSL for Windows is by installing [Git for Windows](https://git-scm.com/install/windows)
```ps2
# PowerShell
$certname = "{certificateName}"    ## Replace {certificateName}
$cert = New-SelfSignedCertificate -Subject "CN=$certname" -CertStoreLocation "Cert:\CurrentUser\My" -KeyExportPolicy Exportable -KeySpec Signature -KeyLength 2048 -KeyAlgorithm RSA -HashAlgorithm SHA256
$mypwd = ConvertTo-SecureString -String 'PASSWORD' -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath "%HOMEPATH%\Desktop\$certname.pfx" -Password $mypwd

openssl pkcs12 -in "%HOMEPATH%\Desktop\$certname.pfx" -nocerts -out "%HOMEPATH%\Desktop\privkey.pem"
openssl pkcs12 -in "%HOMEPATH%\Desktop\$certname.pfx" -clcerts -nokeys -out "%HOMEPATH%\Desktop\fullchain.pem"
```

Since Docker Desktop on Windows uses a WSL2 Linux VM under the hood, you'll need to copy these files into your Linux VM's filesystem and point the `secrets:` section to them as shown in the above example.

## Docker Compose
With our `docker-compose.yml` and `mail.env` files in place, we're ready to build our containers.

Inside this directory, run `docker compose up`. You may need to run this command as the root user if you want to bind to the privileged ports for IMAP, IMAPS, SMTP, and HTTP.

Run `docker compose down` to close the container.
